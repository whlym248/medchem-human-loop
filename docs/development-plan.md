# 逐模块开发与验收计划

目标是逐步把工作流设计变成可复查的实现。每次发布分别记录代码能做什么、在什么输入上实际验证、科学验证还缺什么；未实现的生成器或训练策略不以占位代码冒充完成。

| 顺序 | 交付目标 | 当前状态与验收条件 |
| --- | --- | --- |
| 1 | 运行经验可交接 | 本版补充 `docs/hpc/` 与只读检查工具，区分历史记录、实时证据和未解决问题；不包含账号或私有部署信息 |
| 2 | 可追溯案例库 | 本版实现本地记录校验与检索，隔离合成数据；真实经典药物案例语料仍需查原文、核对实验条件和许可后逐条入库 |
| 3 | 局部结构编辑 | 本版实现指定原子位点的有限芳香编辑规则、固定区域检查和来源记录；不等于通用药物设计器或合成路线验证 |
| 4 | 透明方法选择 | 本版实现规则建议并说明理由；缺少证据时可暂停，扩散后端未提供时明确阻塞，不称为学习策略 |
| 5 | 人工决策与轮次关联 | 本版提供证据快照、HTML 审阅页、决定日志和下一轮母体身份核查；不自动启动真实计算 |
| 6 | 真实案例语料与化学检索 | 按原始来源建立可审核小型真实案例集，加入分子图/变化检索，评估相关性与错误率，保留失败案例 |
| 7 | 计算工具端到端接入 | 统一编辑产物、结构准备、docking 搜索、ADMET 和 MD 的输入身份及证据输出；在获准远程资源上跑完独立的完整集成验证 |
| 8 | 局部约束 diffusion | 选择允许所需用途的具体模型/权重，明确固定骨架与连接位点约束；检查图/3D约束和输入输出身份，用独立基线验证后才标为可用 |
| 9 | 风险收益建议与界面 | 基于可比证据生成多方案报告、未知项和权重敏感性；验证建议是否有来源且不混淆预测与实验，保留人工回退/停止 |
| 10 | 是否需要训练策略 | 在可靠案例、决策反馈和评估集形成后决定；明确状态、动作、奖励、数据隔离和与非学习基线的比较，训练与性能未验证前不称为 RL 系统 |

后续真实模拟只在明确授权的计算资源上进行。默认测试、示例和本地开发不得启动 MD 或产生付费任务。现有研究部署必须继续使用原版本、冻结身份和原检查点规则；新代码不直接覆盖正在运行的体系。

每个模块合并时更新 `implementation-status.md`、对应说明及有意义的测试。完整系统最终验收必须包含自备或可合法分发的真实体系、完整过程证据和失败恢复；合成例子通过不能代替这些工作。
