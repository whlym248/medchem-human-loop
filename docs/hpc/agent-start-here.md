# 新接手 agent：先读此页

**先恢复事实，再操作机器。** 不要看到“GPU 空闲”“网页超时”或一份旧进度表，就创建新实例、重复提交、恢复本地计算或声称任务完成。

以下 `<…>` 都是占位符。由资源所有者在私有交接中填写，公开仓库不保存真实账号、实例信息、路径或余额。

## 0．读取私有交接与最新用户指令

按 [handoff.example.json](handoff.example.json) 建立私有副本，存放在仓库之外。优先级为：最新明确授权/限制、当前实际观察、带时间戳的旧记录、估计。较新的文件名不保证内容较新，必须同时读记录内的观察时间和来源。

先确认这些信息：

- 唯一获准使用的项目和实例/作业分配；预算上限、计费周期和截止时间。
- 本地是否允许 MD、是否允许启动新任务、是否允许重启或改环境；未明确授权的扩大范围不能推定允许。
- 原队列的入口、**明确的只查询 action**、脚本哈希、权威状态文件、共享镜像位置。
- 已完成任务、正在运行任务、待审阅任务、未知状态；最后观察时间和证据。
- 停止监控与停止计算是两件事。定时跟进结束，不代表远端有限队列已经停止。
- 谁负责用户交互登录、谁负责科学审阅、谁接收数据、谁负责最终停止/释放实例。

本项目历史上的“禁止全部本地 MD”是用户的硬性限制。不能因学校访问失败而自动在控制电脑上替补。公开工具支持多种平台，不会自动赋予某台机器运行许可。

## 1．先确定访问卡在哪一层

| 层次 | 能看到什么 | 接下来做什么 |
|---|---|---|
| 学校门户 | 项目/实例页，或统一认证页 | 显式出现账号、密码、验证码要求时，立即告知用户完成登录；不要读、猜、重置密码 |
| 实例内 Linux | 网页桌面/VNC 已连接，但出现 Linux login | 由用户完成这层登录；门户登录成功不代替它 |
| 浏览器控制连接 | 人能看页面，但 agent 操作超时 | 用同一浏览器核对当前 tab/可见状态；最多一次有依据的恢复尝试，未知动作先查是否已生效 |
| 远端任务 | 日志、进程、状态文件能查询 | 只查询已存在任务；浏览器失灵不构成任务失败证据 |

**一旦确认需要登录就找用户，不能把请求埋在长报告中。** 建议表述：“学校统一认证已要求重新登录，请在当前页面完成登录。现有计算是否仍在运行尚待核实，我没有重启队列。” 用户完成一次登录后应重新读取实际页面，不重复索要同一操作。

如果只是一个工具调用超时，没有登录画面或认证错误，记录“控制通道状态未知”，不要直接说“登录过期”。超时的打开/点击可能已经生效；先检查已有页面，避免制造大量重复 tab。

## 2．确认执行位置，再做最低限度查询

只在已授权的学校虚拟机或 GPU allocation 对应的计算节点查询；集群登录节点不能当作 GPU 计算节点。第一次进入终端可查看：

```bash
hostname
pwd
nvidia-smi
df -h
```

主机名、路径、进程和回执属于私有操作记录，发布前应脱敏。这些命令不创建 MD 任务；不要把安装、重启和启动命令接在后面。

仓库新增的独立探针可避免误调用旧队列包装器：

```bash
python3 scripts/hpc_probe.py --workdir "<VM_LOCAL_WORKDIR>" --state "<STATE_JSON>"
```

此命令需在仓库根目录运行，并先把占位符替换为私有交接确认的路径。`--state` 可为绝对路径，或相对于 `--workdir` 的路径。不提供 `--state` 时只查 GPU 和该目录所在磁盘。

输出包括观察时间、主机、磁盘、有限 GPU 信息、状态文件哈希/修改时间及白名单摘要。它**不检查进程存活、不审计检查点、不读轨迹、不证明科学质量**。`completed` 只是所读文件的声明。状态时间较旧、状态来自共享镜像、或机器时钟不一致，都需要注明。

默认仅向标准输出打印；`--out "<NEW_VM_LOCAL_RECEIPT.json>"` 只允许创建新文件，不覆盖、不建目录。不要把回执直接写到正式任务状态路径或 WebDAV 权威位置。退出码：`0` 信息采集成功，`1` 信息不全，`2` 参数/路径/写入错误；`0` 不表示 MD 通过或完成。`--gpu-timeout` 默认为 8 秒、最大 30 秒，仅约束 `nvidia-smi` 子进程；失联挂载导致的系统文件 I/O 阻塞无法由该参数解除。

**先读脚本再说“只读”。** 原私有部署中的某个队列包装器未传参数时会默认启动；即使传 `status`，它也可能复制脚本或写共享快照。新增探针不调用这些包装器、不导入 OpenMM、不创建 CUDA Context、不恢复 checkpoint、不触碰锁，只执行一次 GPU 查询并读取显式状态文件；可选新回执是唯一写入。

## 3．要检查队列时，把证据补齐

轻量探针只是起点。实际验收还应使用经过代码审阅的现有监控器，或分别核对以下信息：

1. 权威 VM 本地状态和内嵌时间；共享文件只作为副本，可能滞后或半写入。
2. 实际 PID、命令身份、进程开始时间/系统 boot ID；PID 可能复用，`/proc/<PID>` 存在不充分。
3. 有限日志尾部、采样 CSV 完整末行、步数增长、数值是否有限；不要每轮重扫整个轨迹。
4. GPU 利用率、显存、磁盘余量，和此前实际速度；一瞬间低利用率不等于卡死。
5. manifest、运行身份、双槽检查点哈希与步数。正在写入的槽可能暂不可读，必须区分写入竞争与损坏。

不要按预计结束时间填完成。不要将旧母药监控器的输出当作后来候选队列的状态。监控脚本也有版本和适用范围，应在交接中绑定脚本哈希及队列身份。

## 4．失败时选择正确下一步

- **网页失败、远端状态未知**：不重启任务。记录最后有效观察；做不依赖新结果的资料工作。
- **显式登录失败**：只请求用户完成正常登录；无需请求其把密码发给 agent。
- **完整日志证实数值错误**：保留输入、attempt、日志和锁证据，先定位原因，再决定新体系或恢复；不盲重试。
- **包装器或状态镜像失败**：检查实际 MD 子进程；控制程序失败与物理模拟失败分开处理。
- **磁盘不足**：先盘点和验证备份；不能删除仍被有效清单引用的轨迹、旧 attempt 或未核验副本。

每轮最多做一次完整必要检查。一个网页操作失败后先重新读取状态，至多一次有依据的恢复；仍失败就记录阻塞并转做独立工作。新的用户登录信息或确切环境变化到来后再恢复，不无限轮询。

## 5．向下一位交接

更新私有 JSON，分开写：已完成计算、已完成分析、已完成科学审阅、已验证备份、当前未知项。附原始证据路径/哈希及观察时间，不把“文件已准备”“已上传”“已执行”合并成一个“已完成”。

最终简报至少回答：现在什么在跑；最后何时确认；下一个安全动作；需要谁登录/决策；资源何时到期；原队列是否实际停止。没有观察到就写未知。
