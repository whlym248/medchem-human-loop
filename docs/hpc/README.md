# 华科 GPU 使用与 agent 交接指南

这是从一次真实学校 GPU 部署整理出的操作经验，适用于人和新接手的 agent。它附在 workflow 仓库内，因为环境、运行身份、检查点和科学审阅直接影响本仓库 MD 工具能否可靠使用；单独拆仓库会让接口和指南更容易脱节。

它不是学校官方使用手册，也不是一键启动脚本。公开入口：[华中科技大学高性能计算平台](https://hpc.hust.edu.cn/)。平台页面、镜像、调度方式和计费规则可能变化，应以当前页面与学校规定为准。

## 阅读顺序

1. **新 agent 首先读 [agent-start-here.md](agent-start-here.md)**：哪些事实必须接续、怎样先看状态、什么时候找用户登录。
2. [deployment-and-operations.md](deployment-and-operations.md)：从驱动、环境到审阅、队列、分析、备份的逐步流程。
3. [incident-log.md](incident-log.md)：本次踩过的坑、已验证的解决办法、未解决部分。
4. [handoff.example.json](handoff.example.json)：不含真实账号和地址的私有交接模板。
5. [../../scripts/hpc_probe.py](../../scripts/hpc_probe.py)：独立的轻量只读探针；无需 OpenMM，默认只打印。

## 能提供什么

- 帮助识别门户登录、虚拟机登录、浏览器控制连接和 MD 进程这几个不同层次。
- 给出证据优先级、有限重试、防重复启动、有效片段和备份原则。
- 记录一次 V100S、Ubuntu 22.04、OpenMM 8.6.1、CUDA 12.9 的历史部署经验。
- 用标准库探针读取一份显式指定的状态 JSON，查询 GPU 和磁盘，并可保存一个新的本地回执。

## 不提供什么

- 不包含真实学校账号、实例 ID、预算、私有路径、凭据、预参数化研究体系或运行中的任务。
- 不提供新实例、改驱动、重启、SSH 密钥安装、登录或计费自动化。
- 不保证旧环境组合今天仍能在某个镜像中求解成功。
- 不把队列的 `completed`、网页成功提示或 CRC 通过当作科学验证。

历史事实截至本项目留存的 2026 年 10 月 3 日记录；整理时没有再次连接学校或运行新 MD。探针的验证是有意义的本地标准库测试，GPU 调用以 stub 代替，不能声称已经在学校实测了这个新探针。

## 给使用者的原理概览

本机是控制端，学校虚拟机/分配到的计算节点是执行端。GPU 加速大量原子间作用力的并行计算；MD 用力场及积分方法逐步推进坐标。以 2 fs 步长为例，20 ns 生产段需要一千万个积分步。网页断线是控制端问题，通常不等于后台程序已停；但只有后台启动、日志和进程等真实证据才能确认它仍在运行。

AI 预测、分子修改建议和 MD 是不同环节。部署成功只建立可计算的环境；技术 pilot 通过只支持进入下一阶段；短程单种子轨迹只支持有限的姿态行为观察。解释边界见 [scientific-interpretation.md](../scientific-interpretation.md)。
