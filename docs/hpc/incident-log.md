# 这次遇到了什么，哪些办法实际有效

本表是 2026 年 10 月 1—3 日项目记录的脱敏复盘，不是当前学校状态。这里的“解决”只指对应问题得到记录中的验证；不表示所有后续问题消失。首次整理时未做新远程实测。

| 问题与观察 | 当时采用的办法 | 证据/结果与适用边界 |
|---|---|---|
| 个人页面余额不足、没有自建实例 | 检查获准老师/共享项目下已有资源，明确唯一实例和预算后复用 | 共享项目资源可用；不应据个人页直接断言学校无算力，或再创建付费实例。真实项目标识和预算不公开 |
| 门户登录后，Linux 首次登录仍未完成 | 把两层登录分开；用户自行设置/输入 Linux 凭据 | 实例登录后来完成；agent 未索取密码内容。重启后可能再次需要 Linux 登录 |
| NVIDIA 驱动包装好了，但 GPU 仍由 `nouveau` 使用 | 安装记录中的 580 server 驱动后重启原实例，再重新登录核验 | 后续 NVIDIA/CUDA 技术检查及真实 pilot 通过；不是所有镜像都应安装同一驱动，重启也需当前授权与作业核查 |
| 相同 OpenMM 版本存在不同 CUDA 构建，本机环境又是 Windows/OpenCL | 先查官方包元数据、固定 Linux CUDA 12 构建，隔离安装并保存实际环境清单 | V100S + OpenMM 8.6.1 + CUDA 12.9 在本次环境运行成功；版本字符串相同不保证 checkpoint 兼容 |
| CUDA 平台“看得见”不等于真实体系能跑 | 分别做驱动、导入/平台、最小 Context 能量检查和真实体系短 pilot | 两项母药真实 CUDA pilot 完成，之后实际读完整质量报告才记审阅；不能把平台列举写成科学验证 |
| 下载 JSON 超时，完整质量报告一直没拿到 | 用网页文件编辑器打开完整 JSON，实际聚焦代码区域，全选复制并读剪贴板 | 完整报告成功读取、保存，技术审阅随后写入；页面结构与剪贴板工具依实际环境，不固定 tab 编号 |
| 状态文件在共享盘进行临时文件原子改名失败 | 将权威状态移到 VM 本地；共享目录只发布普通副本，失败单独记录 | 母药后处理与归档随后完成；共享镜像不是强一致源，监控应识别半写入/陈旧时间 |
| 后处理归档中，审阅 JSON 与配体 JSON 同名 | 归档保留原始目录前缀，并检查成员路径唯一 | 避免覆盖或漏收；归档后 CRC、逐成员 SHA、源稳定与共享副本 SHA 组合验证 |
| 恢复后的旧 trajectory 尾部可能被重复统计 | 独立 attempt、双槽 checkpoint、冻结身份、按有效片段清单分析 | 已有母药分析使用有效清单；新候选没有同等审阅前不能据队列完成记录抄填指标 |
| 本地长计算使控制电脑持续发热 | 保存核验断点后停本地任务；用户明确禁止后未自动恢复 | 保留旧数据，后续 MD 限学校资源；未诊断硬件损伤，也不据降温推定允许重新运行 |
| “获取存储配置失败”，用户重登后恢复 | 用户正常完成学校统一认证，再读实例文件页 | 当次门户问题解决；不是所有读取超时都需用户重新登录，应先看错误/页面 |
| 浏览器超时、VNC 卡顿、长命令字符变形/截断 | 缩短单次操作，优先文件上传加哈希，短命令调用；未知动作先查实际状态 | 部分短操作和编辑器读 JSON 有效；长脚本部署问题没有彻底解决，不能声称已部署的通用候选后处理 |
| VNC 停在 `cat` 接收输入界面，未确认回到 shell prompt | 停止继续发送脚本；请求恢复交互，保留原文件与任务 | 未确认提示符前的 `Ctrl+C` 不能算成功；命令可能只被写进文件，且发信号对象必须确认 |
| 任务估计耗时已到，但网页不能读 | 保留最后时间戳和观察，把当前状态标未知 | 后续门户读到新的队列快照后才更新；没有根据预计时间假称采样/分析完成 |
| 文档写“只读 status”，实际脚本存在副作用 | 本次整理重新审阅旧源码，发现 wrapper 可能先复制文件，status 写共享快照，默认缺省 action 甚至为 start | 已更正文档；新增独立探针完全不调用旧 wrapper。名字叫 `status` 不足以证明无副作用 |

## 没有彻底解决的部分

- **浏览器/VNC 不稳定**：一些操作方法绕过了具体故障，但没有得到可靠、长期自动恢复的通道。不将换 tab、重登一次或工具返回超时当成永久修复。
- **通用候选后处理部署**：本地准备过脚本与传输包、校验过本地文件；远端部署/执行未取得完整确认。不能把旧母药后处理成功扩大为所有候选成功。
- **候选最终科学证据**：最新留存队列文件曾报告若干候选采样完成，但没有同等级的独立轨迹分析、检查点核查与完整备份验收；这里不补造结果。
- **新的公开探针**：代码和隔离的标准库测试完成；没有在学校真实节点上运行过，不具备远端实测背书。

## 需要改进的工作方式

早期在同一种下载/重连方式上投入过多次尝试，且需要用户登录时没有足够快地明确通知。这减少了有效计算结果整理时间。接续时采用如下规则：一次失败先核对状态；至多一次有依据的恢复；明确出现认证页立即找用户；无新证据时转做独立工作。不能用“继续努力”替代具体阻塞、责任人和下一步。

每次报告都区分“已在本地准备”“已上传并核对哈希”“已远端执行”“已读完整结果”“已审阅”“已备份”。一个阶段成功不能自动填满后续阶段。

## 本复盘的依据与可核验边界

整理时读取了原始部署状态记录、逐时运行核查说明、Linux 分阶段环境说明及脚本、候选队列启动/状态源码、候选监控源码、母药后处理源码。公开文本只保留操作规律和必要软件版本，不复制私有状态文件、账号、实例地址、运行目录、余额、截图或密码信息。

特别是：候选监控脚本虽然描述为 read-only telemetry，尾部仍会创建历史目录并写报告；母药后处理源码具有安装依赖、启动分析和归档行为；这些都不是仅凭标题可认定的严格只读工具。公开 `hpc_probe.py` 的权限边界可直接审阅源码和 [测试](../../tests/test_hpc_probe.py)。

这是来源记录驱动的工程经验总结，不是新的 HPC 故障复现实验，也不是学校官方保证。
